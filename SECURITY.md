# SECURITY — Умный кошелёк

## Секреты не хранятся в репозитории

Проект содержит интеграции с платёжными и AI-сервисами, поэтому все ключи
вынесены в переменные окружения. В репозитории **нет** и не должно быть
реальных токенов.

| Файл | Статус | Комментарий |
|---|---|---|
| `.env.example` | ✅ коммитится | шаблон с пустыми/заглушечными значениями |
| `.env` | 🚫 в `.gitignore` | локальная конфигурация разработчика |
| `.ssh/` (приватные ключи) | 🚫 в `.gitignore` | доступ к серверу только локально |
| `certs/` | 🚫 в `.gitignore` | корневые сертификаты для MAX API |
| `deploy/env.production`, `deploy/.env.production.ready` | 🚫 в `.gitignore` | боевые ключи создаются на сервере вручную |

### Как задать свои значения

```powershell
Copy-Item .env.example .env
# затем заполните .env своими ключами
```

Минимально необходимые переменные: `MAX_BOT_TOKEN`, `DATABASE_URL`,
`DJANGO_SECRET_KEY`, `AI_DOSTUP_API_KEY` (для AI-функций),
`YOOKASSA_SHOP_ID` + `YOOKASSA_SECRET_KEY` (для приёма оплаты).

## Рекомендации для production

* `DJANGO_DEBUG=False`, `DJANGO_SECRET_KEY` — случайная строка ≥ 50 символов;
* `WEBHOOK_HOST=127.0.0.1` — наружу только через nginx с HTTPS;
* `MAX_WEBHOOK_SECRET` — длинный случайный секрет в пути вебхука;
* `ROBOKASSA_GATEWAY_TOKEN` / проверка подписи для платёжных callback;
* файл `.env` на сервере с правами `600` и владельцем сервисного пользователя;
* регулярные бэкапы PostgreSQL (см. [DEPLOY.md](DEPLOY.md)).

## Если секрет всё же попал в Git

1. Немедленно отзовите/перевыпустите ключ у провайдера (MAX, AI Dostup, ЮKassa, SSH).
2. Удалите файл из индекса: `git rm --cached <файл>` и добавьте его в `.gitignore`.
3. Если коммит уже отправлен — перепишите историю (`git filter-repo`) и сделайте
   force-push, затем смените все затронутые пароли.
